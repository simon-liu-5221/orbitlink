# 資料倫理與合規

原始 FYP 的風險表把「分析前未匿名化敏感資料」列為 Impact 高 / Probability 中的風險，但正文完全沒有對應的控制措施，全篇只有一句「comply with PDPA regulations」。這份文件補上實際做法。

## 我們處理的是誰的資料

YouTube 留言的作者是真實個人。留言內容、頻道 ID、顯示名稱、留言時間都構成新加坡《個人資料保護法》（PDPA）意義下的個人資料。使用者是平台的客戶，留言者不是，留言者沒有同意被分析。這是本專案最主要的倫理風險。

## 控制措施

### 1. 作者身分假名化

留言作者的 YouTube channel ID 在進入資料庫前先做 HMAC-SHA256：

```python
pseudonym = hmac.new(PSEUDONYM_KEY, author_channel_id.encode(), "sha256").hexdigest()[:16]
```

`PSEUDONYM_KEY` 存在環境變數，不進 git，且每個部署環境不同。資料庫中不存原始 channel ID。

顯示名稱僅在分析執行期間存在記憶體中，用於前端呈現時的 label，不落地。網路圖上的節點標籤預設顯示假名，使用者可在單一 session 內切換顯示原始名稱，但該對照表不持久化。

### 2. 留言原文的保留期限

留言原文只在 `fetching` 到 `analyzing` 階段存在，用於情緒推論。推論完成後：

- 保留：情緒分數、毒性分數、字數、時間戳、假名化的作者、回覆關係
- 刪除：留言原文

例外：使用者可選擇保留原文以便日後檢視，此時原文寫入 `raw_comments` 表並設定 30 天 TTL，由每日排程清除。此選項預設關閉，開啟時前端明確告知保留期限。

### 3. 只呈現聚合結果

前端不提供「列出某個人所有留言」的功能。個人層級的資料只在聚合的脈絡下出現（例如社群成員清單、影響者排名），且不可依單一使用者做跨專案查詢。這防止本工具被當成針對個人的監控工具。

### 4. YouTube API 服務條款

- 僅使用 YouTube Data API v3 官方端點，不做網頁爬取
- 遵守每日配額，配額耗盡時 job 明確失敗而非降級為爬蟲
- 不快取超過 ToS 允許期限的 API 回應
- 應用程式在 UI 標示資料來源為 YouTube

### 5. 平台使用者自身的資料

- 密碼以 argon2id 雜湊
- 使用者可刪除帳號，刪除時級聯清除所有專案與分析結果，30 天內完成
- 資料匯出：使用者可下載自己所有專案資料的 JSON
- 不做行為追蹤，不接第三方分析腳本

### 6. 分析結果的誤讀風險

原 FYP 的風險表已經正確指出「使用者可能在沒有訓練的情況下誤解視覺化或中心性指標」。對應措施：

- 每個指標旁提供說明（betweenness centrality 高代表什麼、不代表什麼）
- 情緒分析結果一併顯示模型在評估集上的準確率
- 社群偵測結果顯示 modularity 分數，並在分數低於 0.3 時提示「網路中沒有明顯的社群結構，以下分組可能不具意義」
- 不提供「這個人是負面帳號」這類會被拿去做針對性判斷的標籤

## 未做到的部分（誠實揭露）

- 留言者無法對本工具行使刪除權，因為我們無法識別他們也無法聯絡他們。緩解方式是假名化與短保留期，但這不是完整的解法。
- 情緒模型在粵語、閩南語與大量表情符號的留言上表現不佳，可能系統性低估某些社群的正面情緒。
- 本工具尚未經過法律審閱。若要商業化，PDPA 下的「合法目的」與「通知義務」需要正式意見。
