# 案例研究

> 在 M8 完成。這份文件是整個專案在求職上最有價值的一份。

一個工具的價值不在於它有幾個功能，而在於它讓人看見了什麼。這份案例研究用 OrbitLink 分析一個真實的 YouTube 頻道，回答一個具體的問題。

## 建議的寫法

### 選題

挑一個你自己有興趣、留言區夠活躍的頻道。問一個具體的問題，例如：

- 這個頻道的留言區有沒有一群穩定的常客，他們跟一次性觀眾的行為差在哪裡？
- 某支爭議影片發布後，留言區的社群結構有沒有改變？
- 情緒最負面的社群，是不是也是互動最密集的社群？

避免「我分析了這個頻道」這種沒有問題的寫法。

### 結構

1. **問題** — 一段。你想知道什麼，為什麼這件事值得知道。
2. **資料** — 頻道、影片數、留言數、時間範圍、擷取日期。
3. **方法** — 建圖方式、跑了哪些演算法、參數。連結到 `algorithm-validation.md`。
4. **發現** — 3 到 5 個發現，每個配一張圖。用具體數字。
5. **反直覺的部分** — 哪個結果跟你原本的預期不同。這一段最值錢。
6. **限制** — 這份分析不能得出什麼結論。取樣偏誤、模型誤差、時間範圍太短。
7. **如果有更多時間** — 下一步會做什麼。

### 寫作原則

- 每個宣稱都要有數字支持
- 不要把相關講成因果
- 情緒分析的結論要一併帶上模型的 F1
- modularity 低的時候不要硬解讀社群
- 誠實寫出你原本以為會看到但沒看到的東西

## 為什麼這份文件重要

面試時「我做了一個社群網路分析平台」跟「我做了一個社群網路分析平台，用它發現這個頻道的核心討論圈其實只有 40 個人，貢獻了 60% 的回覆，而他們的情緒明顯比路過觀眾更兩極」是完全不同的兩件事。

第二種說法證明你不只會寫程式，還會用資料回答問題。這正是分析與資料科學職缺在找的東西。
